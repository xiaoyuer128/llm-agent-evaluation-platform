# 06 测试计划与测试用例

状态 **设计基线 v0.1**。下列测试用例待实现和执行，当前无通过率或覆盖率报告。

## 策略与数据

- 单元覆盖状态转换、请求去重、评分器、指标计算与错误映射。使用固定时钟、随机源和独立期望数据。
- API 契约覆盖 FastAPI 请求校验、HTTP 状态与权限。HTTPX stub 模拟限流、延迟、超时、结构化输出和畸形响应。
- 集成测试使用 PostgreSQL、Redis、独立 Linux Celery Worker 和调度进程。验证真实事务、锁、消息重投和 Worker 中断。Celery eager 测试仅覆盖进程内逻辑。
- 回归夹具包含规则答案、中文开放问答、两个确定性 Agent 工具、金标轨迹和人工结论，数据使用合成或经审批脱敏的内容。
- 基础设施验证用临时数据库、唯一测试队列及服务隔离。异步断言使用截止时间轮询；失败保留请求 ID、运行/执行项 ID、迁移版本、脱敏日志和 JUnit 报告。

## 用例

| T01 | FR-01 | 契约 | 两个适配器执行同一输入；第二个缺少 usage | 均转换成统一响应；第二个用量为空；无密钥字段 |
| T02 | FR-02 | API/集成 | 导入两行，第二行重复 case_key；再执行 dry_run | 返回 422 和行号，行数不变；dry_run 校验通过也不落库 |
| T03 | FR-02 | 集成 | 并发执行发布和导入；发布后再尝试追加 | 校验和对应完整已提交样本；发布后追加返回 409 |
| T04 | FR-03 | 集成 | 并发 10 次发送相同主体、键和体，再用同键换候选 | 一条运行和一套初始事件；延迟重放同 Location；换候选返回 409 |
| T05 | FR-03 | 集成 | 分别在 DB 提交后 Redis 不可用、消息发布后尚未标记、发出后 Redis 数据丢失处中断 | 恢复后到终态；每项最多一条终态结果 |
| T06 | FR-03 | 集成 | Worker W1 领取后暂停，租约过期由 W2 接手，然后恢复 W1 | W1 写回失败，W2 结果唯一；旧尝试记录过期 |
| T07 | FR-03 | 集成 | 一次 429 后成功；持续 503；鉴权 401 | 429 按预算重试，503 达上限终止，401 单次失败 |
| T08 | FR-03 | 集成 | 运行中取消；一个项已完成，一个在途，一个未开始 | 之前成功结果可读，剩余成为取消；终态计数守恒 |
| T09 | FR-04 | 单元 | 数字容差边界、错误答案、布尔与整数、Unicode、缺失 Token | 按规则命中；真正零分与缺失指标区分；覆盖率分母正确 |
| T10 | FR-05 | 集成 | 首次裁判暂态超时、第二次有效；另测必填维度缺失与越界 | 成功候选仅调用一次并跨重试复用；非法输出归类，最终失败得分为空 |
| T11 | FR-05 | 回归 | 金标中加入复制参考答案、冗长错误回答和提示注入文本 | 维度评分与阈值独立校验；裁判只输出结构化证据；通过率记录到报告 |
| T12 | FR-06 | 集成 | 期望查订单一次；Agent 两次查同订单并带一次错参 | 一对一匹配只计一个，重复或错参计入分母；完成状态由独立业务断言决定 |
| T13 | FR-06 | 集成 | 必需工具未调用、工具异常、到达步数上限 | 记录可观测终止原因；无调用的准确率为空，必需调用召回率为 0；业务可判失败 |
| T14 | FR-07 | API | viewer 查样本轨迹；operator 将 A 的 item ID 拼到 B 的路径 | 分别返回 403、404；响应中没有轨迹内容 |
| T15 | FR-07 | API | 并发运行时读列表并翻页；同时间戳创建多个运行 | 游标条件不匹配返回 400；稳定数据无重复遗漏；进行中摘要标记 provisional |
| T16 | FR-08 | 集成 | 从空库和上一版本升级，M2 从 Compose 发起 fake 评测，M4 加入 Agent 轨迹检查 | 迁移顺序正确，健康探针正常，结果和当前阶段支持的轨迹可查 |
| T17 | FR-08 | 演练 | 在隔离环境恢复备份，按文档启动组件 | 样本校验和、运行数和已知结果一致；记录 RPO/RTO |
| T18 | FR-09 | 回归 | 候选相对基线退化，另用不同数据版本或低覆盖率样本 | 分别给出未通过和证据不足，能回链失败例 |
| T19 | FR-01/08 | API/集成 | 提交无权限配置引用、向工具输入嵌入敏感样本标记 | 权限拒绝或脱敏；日志、响应和指标标签不泄露秘密 |
| T20 | FR-03/07 | 性能 | 20 个并发读连接跑 10 分钟，另后台评测 1,000 个 fake 执行项 | 满足 PRD 的 P95 与错误率门槛；执行项和结果数对账一致 |

## 发布门禁

M1 起 CI 运行 lint、单元、契约和基础设施集成测试，验收关联功能时启用对应场景。进入预发前全部适用的 P0 用例须通过，数据库迁移及恢复演练有记录。首轮建议核心状态与评分模块分支覆盖率 ≥ 85%，与全仓覆盖率分开报告。真实裁判和供应商验收在隔离环境按审批额度执行，固定样本、模型、并发和版本。性能报告记录机器规格、样本规模、预热、分位数方法、失败率和提交 SHA；fake 压测与真实供应商端到端结果分别报告。

计划命令随 M1 落地为 `uv run pytest -m "not integration and not live"` 与 `uv run pytest -m integration`。live 用例通过显式开关启用。
